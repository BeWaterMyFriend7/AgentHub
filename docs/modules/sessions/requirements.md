# Sessions 模块需求

> 本文从[总 PRD](../../prd/agenthub-v1.md)第 4 章派生；发生冲突时以总 PRD 为准。

## 目标

让同时运行多个 Agent 和多个内部会话的用户，集中发现真正需要介入的工作，并准确回到原生会话继续处理。

## 会话发现与展示

- 发现同一 Agent 中多个具有稳定原生标识的独立会话。
- 每个会话至少展示 Agent、原生会话 ID、标题、项目或工作目录、运行状态、关注状态、最近活动、更新时间、状态来源和可信度。
- 首页按内部会话统计；进程、窗口和工具数量只作为诊断信息。
- Agent 提供目标、步骤、Todo 或结果时原样透传；缺失时不得推测进度或生成百分比。

## 状态与待处理

- 运行状态包括执行中、等待授权、等待输入、等待验收、执行中断、已关闭和状态未知。
- “是否待处理”是独立关注维度，由统一状态和可信原生事件自动推导，不提供人工标记或清除入口。
- 等待授权、等待输入和执行中断在后续事件表明恢复执行后自动解除。
- 等待验收只有在用户继续发送指令、会话明确关闭或 Agent 上报接受结果时解除；仅打开会话不能视为验收完成。
- 推断状态必须展示来源和可信度，不得冒充 Agent 明确事件。

## 精确恢复与产品边界

- 打开会话必须按稳定原生会话 ID 恢复指定会话，不能只打开 Agent 首页或激活窗口。
- AgentHub 不提供消息输入、权限批准或替代原生客户端执行工作的入口。
- 只能探测进程或窗口时属于有限接入，不纳入核心会话统计。

## 接入等级

- 完整接入：多会话发现、稳定身份、独立状态和精确恢复均通过真实验证。
- 部分接入：缺少规划、事件或部分状态，但仍能识别并精确恢复会话。
- 有限接入：只能判断 Agent 是否运行，不能可靠识别和恢复内部会话。

## 验收标准

- 同一 Agent 至少三个内部会话同时存在时，身份和状态互不串扰。
- 至少两个 Agent 通过真实的多会话发现和按原生 ID 精确恢复验证。
- 有限接入结果不得显示成完整会话，也不得计入会话统计。
