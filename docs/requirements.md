# 1. Agent 配置模块

## 1.1 概述与目标

**原型参考**: [agenthub-prototype.html](../prototypes/agenthub-prototype.html)（Agent 配置标签页）

为 Codex、Claude Code、OpenCode 及后续 Agent 建立一致、可验证、可扩展的接入入口，避免会话、Skill、MCP 和插件各自维护一套 Agent 配置。

### 目标

1. **统一接入**：为所有 Agent 提供统一的配置入口，消除重复配置
2. **自动发现**：自动探测本地已安装的 Agent，减少手动配置工作
3. **可验证性**：提供连接验证和诊断功能，确保配置正确可用
4. **灵活扩展**：支持新 Agent 类型的快速接入，不影响现有配置
5. **安全可靠**：敏感信息通过环境变量管理，不在配置文件中明文存储

---

## 1.2 业务规则

- Agent 类型、Agent 安装和 AgentHub Profile 是不同对象，不得仅用显示名称合并
- 停用 Profile 只停止 AgentHub 发现和操作，不删除 Agent 文件、配置或能力
- 每项能力必须明确声明"支持、不支持或尚未验证"，不能仅因代码路径存在就标记为支持
- 会话观察、任务执行与 Skill、MCP、插件支持状态分别展示，不能互相推导
- Adapter 的平台或版本限制必须对用户可见
- 一个 Agent 接入只有通过对应真实验证，才能从实验性提升为完整支持

---

## 1.3 配置字段规格

### 1.3.1 通用字段

所有 Agent Profile 必须包含以下字段：

| 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `profile_id` | string | 是 | UUID | Profile 唯一标识，创建时自动生成 |
| `profile_name` | string | 是 | - | 用户友好的显示名称，2-50字符 |
| `agent_type` | enum | 是 | - | Agent 产品类型：`codex`/`claude_code`/`opencode`/`hermes` |
| `adapter_kind` | enum | 是 | - | 接入方式：`codex_desktop`/`opencode_desktop`/`opencode_server`/`claude_code_desktop` 等 |
| `enabled` | boolean | 是 | true | 是否启用此 Profile |
| `created_at` | datetime | 是 | 当前时间 | 创建时间 |
| `updated_at` | datetime | 是 | 当前时间 | 最后修改时间 |
| `installation_id` | string | 否 | null | 关联的自动探测安装 ID |

### 1.3.2 各 Agent 特定字段

#### Codex Desktop

| 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `codex_home` | path | 是 | `~/.codex` | Codex 数据目录，包含 state_*.sqlite |
| `db_file_pattern` | string | 否 | `state_*.sqlite` | 状态数据库文件名模式 |
| `deep_link_scheme` | string | 否 | `codex://` | Desktop 深链 URL Scheme |

#### OpenCode Desktop

| 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `db_path` | path | 是 | `~/.local/share/opencode/opencode.db` | OpenCode 本地数据库路径 |
| `cli_executable` | path | 否 | `opencode` | CLI 可执行文件路径或命令名 |

#### OpenCode Server

| 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `server_url` | url | 是 | - | OpenCode Server 地址，如 `http://localhost:8000` |
| `secret_env` | string | 是 | `OPENCODE_SERVER_PASSWORD` | 存储密码的环境变量名 |
| `cli_executable` | path | 否 | `opencode` | CLI 可执行文件路径或命令名 |
| `timeout_seconds` | integer | 否 | 30 | API 请求超时时间（秒），范围 5-300 |
| `verify_ssl` | boolean | 否 | true | 是否验证 SSL 证书 |

#### Claude Code Desktop

| 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `data_dir` | path | 是 | 平台相关 | Claude Code 数据目录 |
| `db_file_name` | string | 否 | `state.db` | 状态数据库文件名 |

### 1.3.3 字段验证规则

#### profile_name
- 长度：2-50 字符
- 允许：字母、数字、空格、中文、`-_()` 等常见符号
- 禁止：纯空格、仅符号
- 唯一性：同一 `agent_type` + `adapter_kind` 组合下不允许重名

#### 路径字段
- 必须是绝对路径或以 `~` 开头的用户目录路径
- 路径存在性检查：**警告但不阻止保存**，允许用户配置尚未启动的 Agent
- 权限检查：如果路径存在，必须具有读取权限

#### server_url
- 格式：有效的 HTTP/HTTPS URL
- 端口：1-65535
- 连接性测试：**可选**，用户点击"测试"按钮时执行

#### secret_env
- 格式：有效的环境变量名（字母、数字、下划线，不以数字开头）
- 存在性检查：**警告但不阻止保存**，运行时从环境读取

#### cli_executable
- 格式：绝对路径或命令名
- 存在性检查：检查文件是否存在或在 PATH 中
- 检查结果为**警告**，不阻止保存

## 1.4 Agent 自动探测

### 1.4.1 探测范围

支持自动探测本地已安装的主流 Agent：
- **Codex**：Desktop 版本、CLI 版本
- **OpenCode**：Desktop 版本、Server 版本（需手动配置地址）
- **Claude Code**：Desktop 版本
- **Hermes**：Desktop 版本、CLI 版本

### 1.4.2 探测状态

| 状态 | 说明 | 颜色标识 |
|------|------|---------|
| **已配置并验证通过** | Agent 已完成配置，连接测试通过，可正常使用 | 绿色 |
| **已探测到** | 自动探测到 Agent 安装，但用户还未添加配置 | 绿色 |
| **已配置，有警告** | Agent 已配置且部分功能可用，但存在问题 | 橙色 |
| **需要配置** | 探测到部分信息，需要用户补充配置 | 蓝色 |
| **未找到** | 标准路径下未发现安装 | 灰色 |

### 1.4.3 平台特定探测路径

#### Windows
- Codex: `%USERPROFILE%\.codex`
- OpenCode: `%LOCALAPPDATA%\opencode`
- Claude Code: `%APPDATA%\Claude\Code`

#### macOS
- Codex: `~/.codex`
- OpenCode: `~/Library/Application Support/opencode`
- Claude Code: `~/Library/Application Support/Claude/Code`

#### Linux
- Codex: `~/.codex`
- OpenCode: `~/.local/share/opencode`
- Claude Code: `~/.config/claude/code`

## 1.5 Profile 管理流程

### 1.5.1 创建流程

#### 手动创建
1. 点击"手动添加"按钮
2. 选择 Agent 类型和接入方式
3. 填写配置字段，必填字段标记清晰
4. 实时验证：字段失焦时执行格式验证
5. 可选：点击"测试"按钮测试连接
6. 保存配置

#### 自动探测添加
1. 首次打开配置页面时自动探测所有支持的 Agent
2. 探测结果按状态分类显示
3. 已探测到的 Agent 可直接添加到配置列表
4. 未探测到的 Agent 可手动配置

### 1.5.2 编辑流程
- Profile 列表中点击"编辑"按钮
- `profile_id`、`agent_type`、`adapter_kind` 不可修改
- 其他字段均可修改
- 保存后自动清除之前的验证结果

### 1.5.3 操作按钮

每个 Agent 卡片提供三个操作按钮：
- **编辑**：修改配置信息
- **测试**：测试连接可用性
- **隐藏/显示**：控制在列表中的可见性

### 1.5.4 隐藏/显示机制
- 用户可以隐藏不常用的 Agent
- 隐藏的 Agent 不在默认列表中显示
- 通过"显示已隐藏"按钮可以查看和恢复隐藏的 Agent
- 隐藏不影响 Agent 的功能，只是UI展示控制

---

## 1.6 配置验证与诊断

### 1.6.1 验证时机
- **手动触发**：用户点击"测试"按钮
- **定期验证**：后台定期检查已启用 Profile 的连接状态（每5分钟）

### 1.6.2 验证项目

#### Codex Desktop
1. 检查 `codex_home` 目录是否存在
2. 检查是否有匹配 `db_file_pattern` 的文件
3. 尝试打开最新的数据库文件（只读模式）
4. 验证数据库 schema（检查 `threads` 表是否存在）

#### OpenCode Desktop
1. 检查 `db_path` 文件是否存在
2. 尝试打开数据库（只读模式）
3. 验证数据库 schema
4. 检查 `cli_executable` 是否可执行（如果配置了）

#### OpenCode Server
1. 检查环境变量 `secret_env` 是否存在
2. 尝试连接 `server_url`（带超时）
3. 发送 API 请求验证认证
4. 记录 API 版本信息

### 1.6.3 诊断建议

| 错误原因 | 修复建议 |
|---------|---------|
| 路径不存在 | Agent 可能未安装或数据目录位置不正确，请检查安装路径 |
| 无读取权限 | 请检查文件系统权限，或以管理员身份运行 AgentHub |
| 数据库打开失败 | 数据库文件可能损坏或被其他进程锁定，请关闭 Agent 后重试 |
| Server 连接失败 | 无法连接到服务器，请检查服务器是否运行以及网络连接 |
| 认证失败 | 认证失败，请检查环境变量是否设置了正确的密码 |
| CLI 不可执行 | 找不到 CLI 工具，精确恢复功能将不可用，可以指定完整路径 |

## 1.7 验收标准

### 1.7.1 核心功能验收

| 验收项 | 验收标准 |
|--------|----------|
| 多 Profile 支持 | 能够为同一 Agent 产品创建多个 Profile |
| Profile 隔离 | 单个 Profile 校验失败不影响其他 Profile |
| 字段验证 | 所有验证规则正确执行，错误提示准确 |
| 自动探测 | 首次打开配置页面自动展示所有 Agent 探测状态 |
| 探测到可添加 | 探测到的 Agent 配置可添加并通过验证 |
| 隐藏/显示功能 | 可以隐藏 Agent，通过按钮切换显示状态 |
| 按钮精简 | 只保留编辑、测试、隐藏三个按钮 |

### 1.7.2 安全性验收

| 验收项 | 验收标准 |
|--------|----------|
| 密码不存储 | 配置文件、日志、API响应中不包含密码 |
| 环境变量读取 | 运行时从环境读取密码 |
| 配置文件权限 | agents.json 设置为用户只读（600） |
| 只读数据库 | 数据库访问使用只读模式 |

# 2. 会话管理模块

## 2.1 概述与目标

**原型参考**: [agenthub-prototype.html](../prototypes/agenthub-prototype.html)（会话管理标签页）

让同时运行多个 Agent 和多个内部会话的用户，集中发现真正需要介入的工作，并准确回到原生会话继续处理。

### 目标

1. **集中监控**：统一展示所有 Agent 的会话状态，避免在多个工具间切换
2. **精准介入**：自动识别需要用户介入的会话，减少无效检查
3. **精确恢复**：提供一键恢复功能，准确打开目标会话继续工作
4. **灵活管理**：支持用户标记、筛选、搜索会话，快速定位关注点
5. **状态透明**：明确标识状态来源和可信度，不误导用户决策

---

## 2.2 会话发现与展示

### 2.2.1 整体页面布局

页面采用三层结构设计：

#### 顶部区域：数字大屏 + 操作记录
- **数字大屏**（左侧，占主要区域）：显示四个统计卡片，可点击跳转到对应筛选
  - 总会话数
  - 执行中
  - 需要介入
  - 待跟进
- **操作记录**（右侧）：滚动显示用户操作和会话记录
  - 记录用户的操作行为（标记、状态修改、忽略等）
  - 记录会话的状态变化
  - 支持一键清空所有记录
  - 固定高度，超出部分自动滚动

#### 中部区域：待处理 + 运行中
两个固定高度的区域并排展示，各占50%宽度：
- **待处理会话**（左侧）：等待授权、等待输入、执行中断的会话
- **运行中会话**（右侧）：正在执行的会话
- 固定高度（约300px），内容超出时可滚动
- 支持快速查看和操作，无需滚动到底部

#### 底部区域：所有会话
完整的会话列表，带搜索筛选功能：
- 搜索框：搜索项目名称或会话标题
- 筛选器：按 Agent 类型、标签筛选
- 会话列表：显示所有会话的完整信息

### 2.2.2 会话基本信息

每个会话展示：
- Agent 名称（不显示完整路径）
- 项目名称（不显示路径）
- 会话标题
- 运行状态徽章
- 用户标记标签
- 更新时间

### 2.2.3 Dashboard 统计

页面顶部数字大屏显示四个统计卡片，可点击跳转到对应筛选：
- **总会话数**：点击显示所有会话
- **执行中**：点击筛选执行中的会话
- **需要介入**：点击筛选需要介入的会话
- **待跟进**：点击筛选用户标记为待跟进的会话

### 2.2.4 操作记录功能

操作记录面板记录以下信息：
- 用户操作：标记会话、修改状态、忽略会话、打开会话等
- 系统事件：会话状态变化、刷新完成等
- 时间戳：每条记录显示发生时间（HH:MM格式）
- 消息类型：
  - 普通消息（绿色边框）
  - 信息消息（蓝色边框）
  - 警告消息（橙色边框）
  - 错误消息（红色边框）
- 最多保留20条记录，超出自动删除最旧记录
- 支持一键清空所有记录

## 2.3 状态管理

### 2.3.1 运行状态

| 状态 | 说明 | 颜色 |
|------|------|------|
| 执行中 | Agent 正在执行任务 | 绿色 |
| 等待授权 | 等待用户授权某项操作 | 橙色 |
| 等待输入 | 等待用户输入信息 | 黄色 |
| 等待验收 | 任务完成，等待用户验收结果 | 紫色 |
| 执行中断 | 任务异常中断或失败 | 红色 |
| 已关闭 | 会话已正常结束 | 灰色 |
| 状态未知 | 无法确定当前状态 | 浅灰 |

### 2.3.2 系统关注状态

- "是否需要介入"是独立关注维度，由统一状态和可信原生事件自动推导
- 不提供人工覆盖入口
- 等待授权、等待输入和执行中断在后续事件表明恢复执行后自动解除
- 等待验收只有在用户继续发送指令、会话明确关闭或 Agent 上报接受结果时解除

---

## 2.4 用户标记

### 2.4.1 标记功能

用户可以对会话进行两种标记：
1. **标记**：添加标签、备注、提醒时间
2. **忽略**：标记会话为已忽略，表示暂时无需处理
   - 忽略状态独立于会话运行状态
   - 已忽略的会话可以取消忽略
   - 忽略时可以填写忽略原因
   - 所有会话都可以忽略，不限于中断状态

### 2.4.2 标签系统

#### 预定义标签
- 待测试
- 需讨论
- 等待资源
- 低优先级
- 需优化
- 等待依赖

#### 自定义标签规则
- 标签长度：1-20 字符
- 每个会话最多 5 个标签
- 标签跨会话共享（输入时显示历史标签建议）
- 支持在标记对话框中选择已有标签或输入新标签

### 2.4.3 提醒时间

快速选择选项：
- 1小时后
- 3小时后
- 明天上午9:00
- 下周一上午9:00
- 不设置提醒

### 2.4.4 操作按钮

每个会话卡片提供四个操作按钮（所有会话都显示完整四个按钮）：
- **查看**：打开会话详情或恢复到 Agent 中
- **标记**：添加标签、备注、提醒
- **状态**：修改会话状态
- **忽略/取消忽略**：
  - 未忽略的会话显示"忽略"按钮，点击后弹出对话框填写忽略原因
  - 已忽略的会话显示"取消忽略"按钮，点击后直接取消忽略状态
  - 忽略状态不改变会话的运行状态，只是标记为已忽略
  - 已忽略的会话会在标题旁显示"已忽略"徽章

---

## 2.5 筛选与搜索

### 2.5.1 筛选维度

| 筛选维度 | 选项 |
|---------|------|
| Agent | 全部 / Codex / OpenCode / Claude Code |
| 项目名称 | 全部项目 / 具体项目名称（从现有会话动态生成） |
| 标签 | 全部标签 / 具体标签 |
| 状态 | 全部状态 / 执行中 / 等待授权 / 等待输入 / 执行中断 / 已关闭 |
| 是否忽略 | 全部 / 未忽略 / 已忽略 |
| 搜索 | 搜索项目名称和会话标题 |

### 2.5.2 搜索行为
- **实时搜索**：输入后 300ms 自动执行搜索（防抖）
- **最小长度**：至少输入 2 个字符才触发搜索
- **大小写**：不区分大小写
- **搜索范围**：项目名称、会话标题

### 2.5.3 快速筛选

Dashboard 统计卡片可点击：
- 点击"总会话数"：显示所有会话
- 点击"执行中"：筛选执行中的会话
- 点击"需要介入"：筛选需要介入的会话
- 点击"待跟进"：筛选待跟进的会话

### 2.5.4 筛选组合

所有筛选条件支持组合使用：
- 可以同时按 Agent、项目、标签、状态、忽略状态进行筛选
- 搜索框与其他筛选条件可以组合
- 所有条件之间是"与"的关系（必须同时满足）

### 2.5.5 项目筛选

项目下拉列表动态生成：
- 自动从当前所有会话中提取不重复的项目名称
- 按字母顺序排序
- 页面加载时自动初始化

## 2.6 会话显示配置

### 2.6.1 卡片内容（精简版）

每个会话卡片包含：
- **状态条**：左侧颜色条表示运行状态
- **标题行**：会话标题 + 状态徽章 + 标签徽章
- **信息行**：项目名称 · Agent 名称 · 更新时间
- **操作按钮**：查看、标记、状态、忽略

**不显示的内容**：
- ~~项目完整路径~~（只显示项目名称）
- ~~当前目标~~
- ~~最近活动~~

### 2.6.2 状态可视化

#### 状态条颜色
- 执行中：绿色
- 等待授权/等待输入：橙色/黄色
- 执行中断：红色
- 已关闭：灰色

#### 状态徽章
- 小型徽章显示在标题后
- 使用对应状态的背景色
- 显示状态文字（执行中、等待、中断、已关闭）

#### 标签徽章
- 蓝色背景徽章
- 显示在状态徽章后
- 最多显示3个标签，超出显示"+N"

## 2.7 刷新与同步策略

### 2.7.1 刷新时机

#### 自动刷新
- **间隔**：可配置，默认 60 秒
- **范围**：所有已启用的 Agent Profile
- **条件**：页面可见且没有正在进行的手动刷新

#### 手动刷新
- **触发**：用户点击"刷新"按钮
- **范围**：全部 Profile
- **反馈**：显示刷新进度和加载指示器

### 2.7.2 刷新流程

1. 触发刷新：自动定时或手动点击
2. 执行刷新：并发调用所有已启用 Profile 的 Adapter，超时 30 秒
3. 合并数据：以 `Profile ID + 原生会话 ID` 为键合并会话
4. 更新 UI：刷新会话列表和统计数字，保持用户当前的筛选和滚动位置
5. 错误处理：单个 Profile 刷新失败不影响其他 Profile

### 2.7.3 性能优化

- 最多同时刷新 5 个 Profile
- Agent 会话列表缓存 60 秒
- 手动刷新强制清除缓存
- 会话数量超过 50 个时启用虚拟滚动
