# AgentHub 路线图

## 阶段 0：需求与设计基线

- 完成 V1 总 PRD、领域语言、技术设计、ADR 和核心 BDD。
- 明确单应用、跨平台链接、会话边界和来源删除规则。
- 确认中央能力来源策略及首批 Agent 支持顺序。

## 阶段 1：主应用基础

- 建立统一 Agent Profile、SQLite 和审计模型。
- 将现有 Mock 会话应用整理为模块化主应用。
- 引入测试运行器、API 测试和 Adapter 契约测试。

## 阶段 2：真实会话接入

- 完成首批 Agent 候选接入方式调研，具体对象和验证项以 [`todo.md`](./todo.md#会话接入) 为准。
- 优先实现一个 Server/API 型 Agent Adapter，再实现一个 Hook/本地数据型 Agent Adapter。
- 完成会话发现、独立状态映射、待处理自动解除、规划透传和精确恢复验收。
- 至少两个 Agent 必须通过“同一 Agent 多会话独立展示并能按原生 ID 精确恢复”的真实验证，才能完成本阶段。

## 阶段 3：整合 Skill 管理

- 从 SkillBridge 提取扫描、清单、共享、安全和回滚能力。
- 合并 Agent 配置、数据库、审计和 UI。
- 完成 Windows、macOS、Linux 目录链接契约与集成测试。

## 阶段 4：MCP 管理

- 先实现只读发现、配置归一化、能力枚举和健康检查。
- 再实现配置修改、目录共享、敏感信息保护和回滚。

## 阶段 5：Agent 插件管理

- 实现插件清单、版本、来源、Manifest 和内含能力。
- 实现共享、所有权、卸载、更新冲突和审计。
- 完成至少两个 Agent 的真实插件生命周期验收。

## 阶段 6：桌面体验与稳定性

- 完成桌面打包、托盘、通知和开机启动。
- 增加中断恢复、失败重试、性能和安全测试。
- 建立三平台发布和验证流程。
