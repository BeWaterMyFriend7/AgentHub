# Workflows 模块测试策略

## 状态机单元测试

- 草稿、排队、执行、暂停、完成、失败和取消转换。
- 完成后只推进一个下一任务。
- 等待输入、等待授权、执行中断和未知状态均停止自动推进。
- 失败后的停止、人工跳过和恢复策略。

## Adapter 契约测试

- 新会话启动和指定会话继续都返回稳定原生会话 ID。
- 相同 TaskRun 幂等键重复调用不会重复发送任务。
- 不支持精确发送、工作目录或会话继续时返回明确能力等级。

## 集成测试

- 持久化 Workflow 后重启应用，从正确 TaskRun 恢复。
- Sessions 的重复、乱序或延迟事件不会导致重复推进。
- 同项目继续会话，跨项目创建新会话，工作目录和身份互不串扰。
- 暂停期间收到完成事件时保持一致，并在恢复时只推进一次。

## API 与 UI 验收

- 展示当前任务、总体状态、暂停或失败原因和历史 TaskRun。
- 已开始任务提供准确的“打开会话”入口。
- 用户不能编辑已执行历史来伪造结果，也不能在未确认时自动生成新任务。

## 真实验证

至少选择一个支持稳定事件和精确发送的 Agent，验证三个顺序任务自动执行；再使用两个项目验证跨项目隔离。证据产生后保存到 `verification/YYYY-MM-DD-topic.md`。
