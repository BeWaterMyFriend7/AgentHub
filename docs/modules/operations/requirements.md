# Operations 模块需求

本文是 Operations 模块需求事实来源。应用级本地安全原则见[系统架构](../../architecture/architecture.md#公共基础设施)。

## 目标

让能力共享、原生配置变更、卸载、插件更新和来源删除等操作可预检、可确认、可审计，并尽可能可恢复，避免误删真实内容或静默覆盖用户修改。

## 操作类型

- 启用或停用共享安装。
- 新增、修改、启用、停用或删除 Agent 原生能力配置。
- 卸载某个 Agent 中的能力安装。
- 安装、更新或卸载 Agent 插件。
- 删除能力来源。
- 永久清除来源恢复备份。

## 公共规则

- 操作前规范化路径、限制允许根目录，并校验对象身份、所有权、兼容性和目标状态。
- 不得对磁盘根目录、用户主目录或 Agent 能力根目录本身执行递归删除；即使这些路径位于配置范围内，也只能操作经过身份验证的具体能力来源或安装条目。
- 目标存在真实目录或用户修改时不得自动覆盖，应展示冲突和影响。
- 目录链接只表示内容引用；建立链接后仍需完成原生注册、刷新和加载验证。
- 修改操作记录操作者、对象、前后状态、步骤、结果、错误和备份位置。
- 执行前展示自动回滚、补偿恢复、人工恢复或不可逆四种恢复等级。

## 跨平台目录共享

- Windows 使用 NTFS Junction；macOS/Linux 使用 Symbolic Link。
- Windows 必须覆盖 ReparsePoint、盘符差异、路径占用和权限错误。
- macOS/Linux 必须覆盖 Symbolic Link、文件权限、路径大小写和断链行为。
- 停用共享时只删除已验证且确实指向预期来源的链接。
- 不得将路径文本相同视为链接验证成功，必须解析最终目标并检测断链。

## 卸载与来源删除

- 普通卸载只影响一个 Agent 中的安装，不删除能力来源或其他 Agent 安装。
- 用户从来源位置发起卸载时，必须识别为全局“删除能力来源”。
- 删除前展示所有引用安装、受影响 Agent、插件关系和可能丢失的用户修改，并使用独立确认。
- 确认后先做完整预检，再按可恢复顺序移除原生注册和共享链接，最后删除活动来源。
- 任一前置依赖无法安全处理时不得删除来源。
- 隔离备份不再视为已安装能力；永久清除备份需要再次确认。

## 插件所有权规则

- 被多个插件引用的 Skill 在卸载单个插件时保留。
- 插件独占且被用户修改的 Skill 可以随插件卸载，但必须明确提示并备份。
- 插件独占 MCP 配置随插件卸载，仍需审计和可恢复备份。
- 插件更新与用户修改冲突时由用户选择保留修改、采用更新或取消。

## 验收边界

- 启用、停用、卸载和回滚行为确定且可重复，重复请求不会产生额外副作用。
- 任一步骤失败时不损坏真实来源；自动补偿失败时明确进入人工恢复状态并保留证据。
- Operations 与 Platform Adapter 契约测试覆盖预检、幂等、补偿、路径穿透和链接身份验证。
- Windows、macOS、Linux 分别完成等价的文件系统集成验证；未验证平台只能标记为实验性。
