# Workflows 模块需求

本文是 Workflows 模块需求事实来源。

## 目标

让用户为一个或多个项目预先安排任务，系统在当前任务可靠结束后自动发送下一任务，并持续展示队列状态及每项结果对应的原生会话。

## 队列与任务

- 一个 Workflow 包含一个或多个有序 Task，任务可以属于相同或不同项目。
- 每个任务至少记录标题、指令、工作目录或项目、目标 Agent/Profile、顺序和会话延续策略。
- 用户可以在未执行任务之间调整顺序、暂停队列、恢复队列或取消未开始任务。
- 已开始和已完成任务保留原顺序与历史状态，不因后续编辑被重写。

## 自动推进

- 任一时刻一个 Workflow 默认只有一个正在执行的任务。
- 当前任务收到可信完成事件后，系统自动启动下一任务。
- 等待输入、等待授权、执行中断或状态未知时暂停自动推进，并展示暂停原因。
- 任务失败后的默认策略是停止队列；继续执行或跳过必须由用户明确选择。
- 重启 AgentHub 后不得重复发送已经成功启动的任务，推进操作必须幂等。

## 项目与会话策略

- 同一项目的后续任务默认继续上一任务会话，以保留上下文。
- 跨项目任务默认创建新会话，避免工作目录和上下文串扰。
- 用户可以为单个任务明确选择继续指定会话或创建新会话，但目标必须可由 Agent Adapter 精确识别。
- 每次 TaskRun 保存 `agent_id`、稳定原生会话 ID、开始时间、结束时间、最终状态和结果摘要。
- 已完成任务提供“打开会话”入口，由 Sessions 模块执行精确恢复。

## 状态展示

- Workflow 状态至少包括草稿、排队中、执行中、已暂停、已完成、失败和已取消。
- TaskRun 状态至少包括待执行、启动中、执行中、等待介入、已完成、失败、已跳过和已取消。
- 页面展示当前任务、总体进度、暂停原因、失败原因和各任务会话定位。
- Agent 没有提供可信完成事件时不得推测任务完成或自动推进。

## 产品边界

- 自动发送排队任务只通过 Workflows Interface 发起；跨模块归属见 [ADR-0009](../../architecture/adr/0009-workflows-and-session-follow-up-boundary.md)。
- 本能力是对早期“AgentHub 不发送会话消息”边界的受控扩展，只允许发送用户预先确认并进入队列的任务。
- Workflows 只发送用户预先确认的任务内容，不自动生成新的业务任务。
- Workflows 不提供脱离任务队列的任意即时聊天，也不提供权限批准入口。
- 自动执行能力按 Agent/Profile 独立声明；只支持会话观察和打开的 Agent 不得显示为支持任务编排。
- Workflows 不解释 Agent 原生会话格式，由执行 Adapter 和 Sessions 模块提供稳定 Interface。

## 验收边界

- 三个顺序任务能够按完成事件依次启动，任一时刻不会重复启动同一 TaskRun。
- 等待输入或失败会暂停队列，人工处理后可以从正确位置恢复。
- 跨两个项目执行时工作目录和会话身份不串扰。
- 每个已开始任务都能定位到实际原生会话；无法精确关联时必须标记为有限支持。
