# Sessions 模块需求

本文是 Sessions 模块需求事实来源。任务排队和自动推进归 [Workflows 模块](../workflows/requirements.md)。

## 目标

让同时运行多个 Agent 和多个内部会话的用户，集中发现真正需要介入的工作，并准确回到原生会话继续处理。

## 会话发现与展示

- 发现同一 Agent 中多个具有稳定原生标识的独立会话。
- 每个会话至少展示 Agent、原生会话 ID、标题、项目或工作目录、运行状态、关注状态、最近活动、更新时间、状态来源和可信度。
- 首页按内部会话统计；进程、窗口和工具数量只作为诊断信息。
- Agent 提供目标、步骤、Todo 或结果时原样透传；缺失时不得推测进度或生成百分比。

## 状态与待处理

- 运行状态包括执行中、等待授权、等待输入、等待验收、执行中断、已关闭和状态未知。
- “是否需要系统介入”是独立关注维度，由统一状态和可信原生事件自动推导，不提供人工覆盖入口。
- 等待授权、等待输入和执行中断在后续事件表明恢复执行后自动解除。
- 等待验收只有在用户继续发送指令、会话明确关闭或 Agent 上报接受结果时解除；仅打开会话不能视为验收完成。
- 推断状态必须展示来源和可信度，不得冒充 Agent 明确事件。

## 用户跟进标记

- 用户跟进标记是对早期”不提供人工标记”边界的受控扩展，只允许记录后续处理意图，不允许人工改写系统关注状态。
- 用户可以将暂停或需要稍后处理的会话标记为”待跟进”，并填写标签、备注和可选提醒时间。
- 用户可以将中断会话标记为”忽略”，表示该中断是正常退出或无需处理，标记后不再显示在待处理列表中。
- 用户跟进标记是 AgentHub 本地元数据，不改变 Agent 原生运行状态，也不能冒充系统推导的关注原因。
- 系统关注状态与用户跟进标记分别展示、筛选和统计。
- 标记必须绑定稳定的 Agent/Profile 与原生会话 ID；会话重新发现后仍能恢复。
- 用户可以手动取消跟进标记，但不能用该操作清除等待授权、等待输入或执行中断等真实状态。

## 会话筛选与导航

- 主页面统计数字（会话总数、执行中、等待介入、等待验收、任务中断）支持点击跳转到对应状态的会话列表。
- 支持按状态筛选会话：全部状态、执行中、等待授权、等待输入、等待验收、任务中断、已关闭、状态未知。
- 支持按关键字搜索会话标题、项目名称、Agent 名称、当前目标和当前步骤。
- 支持显示/隐藏已忽略的会话，默认隐藏已忽略会话以减少干扰。
- 已忽略的会话在列表中以视觉区分样式显示（半透明灰色背景）。

## 精确恢复与产品边界

- 打开会话必须按稳定原生会话 ID 恢复指定会话，不能只打开 Agent 首页或激活窗口。
- Sessions 模块不提供消息输入、权限批准或任务调度；自动发送工作由 Workflows 模块通过独立执行 Adapter 完成。
- 只能探测进程或窗口时属于有限接入，不纳入核心会话统计。

## 接入等级

- 完整接入：多会话发现、稳定身份、独立状态和精确恢复均通过真实验证。
- 部分接入：缺少规划、事件或部分状态，但仍能识别并精确恢复会话。
- 有限接入：只能判断 Agent 是否运行，不能可靠识别和恢复内部会话。

## 验收标准

- 同一 Agent 至少三个内部会话同时存在时，身份和状态互不串扰。
- 至少两个 Agent 通过真实的多会话发现和按原生 ID 精确恢复验证。
- 有限接入结果不得显示成完整会话，也不得计入会话统计。
- 用户标记会话后刷新或重启 AgentHub，标记、备注和提醒时间仍然存在。
