# 测试与验证策略

## 测试层次

1. 单元测试覆盖状态映射、解析器、路径校验、能力归一化、冲突检测和敏感信息隐藏。
2. 契约测试用统一预期验证每个 Agent Adapter 的多会话发现、稳定原生标识、状态与关注映射、规划缺失行为、事件更新、接入等级和精确恢复；能力 Adapter 另行验证发现与变更契约。
3. 集成测试使用临时目录或临时配置，验证备份、回滚、幂等性和审计记录。
4. API 测试验证响应模型、错误、授权和并发行为。
5. UI 验收测试覆盖会话统计、待处理汇总、状态来源与可信度、有限接入提示，以及能力清单过滤、状态矩阵、确认操作、失败反馈和敏感信息隐藏。

涉及原生破坏性操作的测试只能作用于已验证的临时夹具。平台集成测试必须分别覆盖 Windows Junction 与 macOS/Linux Symbolic Link，并验证链接创建与解析、断链识别、卸载仅移除链接且保留源目录，以及来源删除前的影响预检与确认流程。

真实 Agent 接入验证应同时启动至少三个内部会话，确认会话身份和状态互不串扰，并逐个验证按原生会话 ID 精确恢复。只能打开工具首页或激活窗口的结果应记录为有限接入，不能作为通过证据。

## 验证证据

每次有意义的验证都应在 `verification/` 下新增一份带日期的记录，包含范围、环境、命令、结果和已知缺口。生成日志应通过链接引用或加入忽略规则，不应整段复制到架构文档中。
