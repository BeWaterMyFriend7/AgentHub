# Skill、MCP 与插件管理需求

> **状态：已并入总 PRD，非独立事实来源。** 本文仅保留能力管理专题的推导上下文；如与 [`agenthub-v1.md`](./agenthub-v1.md) 不一致，以总 PRD 为准。新增或变更需求应先修改总 PRD，再按需同步本文，避免形成两套产品口径。

## 目标

将 AgentHub 从会话聚合管理台扩展为跨 Windows、macOS、Linux 的本地能力管理中枢，统一管理 Codex、OpenCode、Claude Code 及未来 Agent 中的 Skill、MCP Server 和 Agent 插件。

## 共有能力

所有能力类型都需要支持：发现、来源与安装识别、各 Agent 可用性、兼容性、健康状态、启用与停用、目录同源共享、原生加载验证、审计历史及安全恢复。不同工具的原生格式和注册方式由对应适配器负责处理。

能力安装卸载与能力来源删除必须严格区分：前者只影响一个 Agent，后者是影响所有引用安装的全局完全删除。用户在来源位置执行卸载时，必须展示完整影响范围并进行独立确认；恢复备份的永久清除需要再次确认。

## Skill 管理

- 复用 `src/skill_bridge/` 中的扫描器、目录聚合、状态模型、备份、链接和回滚设计，并合并到唯一的 AgentHub 应用。
- 提供 Skill × Agent 状态矩阵，区分源目录、共享链接、本地副本、缺失、冲突、断链和无效状态。
- 未经明确确认和备份，不得覆盖真实目录。

## MCP 管理

- 从各个受支持 Agent 的配置中发现 MCP Server 定义。
- 对目录型 MCP 包支持与 Skill 相同的单一来源和跨 Agent 链接共享；链接后仍需完成原生配置及加载验证。
- 统一表示 Server 身份、传输方式、命令或端点、启用状态、所属配置、暴露工具和健康检查结果。
- UI、日志、导出和诊断信息必须隐藏密钥等敏感内容。
- 应用配置前先验证，并保留旧版本用于回滚。

## 插件管理

- 插件仅指 Agent 原生插件。通过原生 Manifest 或 Catalog 发现已安装及可安装插件。
- 对目录型插件支持单一来源和跨 Agent 链接共享；链接后仍需验证 Agent 已经加载。
- 展示版本、来源、内含 Skill/MCP/App、兼容性、启用状态、可用更新和校验失败信息。
- 安装、更新、启用、停用和移除必须经过原生插件适配器，并产生审计记录。
- 移除时必须区分生成缓存和用户编写的插件数据。
- 被多个插件引用的 Skill 在卸载单个插件时保留；插件独占 Skill 即使被修改也随插件卸载，但必须提示并建立恢复备份。
- 插件更新与用户修改冲突时由用户选择，不允许自动覆盖。
- 插件携带的 MCP 配置由插件独占，可以随插件卸载。

## 范围边界

首个版本支持 Windows、macOS、Linux 本地单用户，不包含云端市场、团队策略下发、自动更新或静默执行破坏性清理。

## 验收方向

每种能力类型至少需要在两个 Agent 上完成独立发现以及可确定的启用、停用行为，之后才能标记为“完整支持”。
