# Operations 模块设计

## 统一操作模型

- `OperationPlan`：目标、影响范围、步骤、确认要求和恢复等级。
- `PreflightResult`：路径、权限、兼容性、所有权、冲突和依赖检查结果。
- `OperationStep`：可执行步骤及其补偿动作。
- `BackupReference`：隔离备份的位置、内容指纹和保留策略。
- `AuditRecord`：操作者、对象、前后状态、步骤结果、错误和恢复信息。

## 执行流程

1. 从 `agents` 和 `capabilities` 读取目标、支持能力、来源与所有权。
2. 构建只读影响清单和操作计划。
3. 完成全部预检，并向用户展示冲突、修改、影响和恢复等级。
4. 获得与操作类型匹配的明确确认；来源删除和永久清除不能复用普通卸载确认。
5. 按计划执行备份、文件链接或原生配置步骤，并逐步记录审计。
6. 每一步后验证文件系统与 Agent 原生状态。
7. 失败时逆序执行自动回滚或补偿；无法自动恢复时给出人工恢复材料。
8. 完成后重新扫描事实来源，使读模型收敛。

## 平台链接 Adapter

统一接口提供创建链接、解析目标、验证链接、移除链接和检测断链：

- Windows：NTFS Junction、ReparsePoint、盘符和占用错误。
- macOS/Linux：Symbolic Link、权限、相对目标和大小写差异。

删除前必须同时验证目标路径位于允许根目录、对象为预期链接类型、解析后的来源与操作计划一致。真实目录永远不能走“移除链接”的快捷路径。

## 来源删除顺序

影响分析 → 独立确认 → 全量预检 → 备份必要内容 → 移除原生注册 → 移除共享链接 → 删除活动来源 → 刷新清单 → 写入最终审计。任一前置步骤失败时停止在删除活动来源之前。

## 安全边界

- 只允许本机调用，修改请求需要防跨站或等价本地授权保护。
- 路径操作限定在已配置的 Agent 能力目录、来源目录和备份目录。
- 允许根目录只用于限定边界，不能作为递归删除目标；磁盘根目录、用户主目录和 Agent 能力根目录本身始终禁止递归删除。
- 秘密不进入操作计划、日志、数据库或诊断输出。
- 并发操作按来源和目标安装加锁，重复请求保持幂等。

## 当前实现

- `src/agent_hub/operations/models.py`：操作请求、计划、预检问题、步骤、确认、恢复等级、结果和审计模型。
- `src/agent_hub/operations/manager.py`：通过 `plan/execute/rollback` Interface 统一共享安装的路径预检、真实目录备份、链接创建或移除、执行后验证和逆序恢复。
- `src/agent_hub/operations/audit.py`：当前内存审计实现，后续可替换为持久化 Adapter。
- `src/agent_hub/platform/links.py`：Windows Junction 与 macOS/Linux Symbolic Link Adapter。

当前执行范围仅包括启用和停用共享安装。普通卸载、来源删除、永久清除、插件更新、原生 Agent 配置变更、并发锁与持久化审计尚未开放，不能通过当前 Interface 绕过。
