# Operations 模块测试策略

## 单元测试

- 路径规范化、越界、链接解析和允许根目录判断。
- 磁盘根目录、用户主目录和 Agent 能力根目录本身的递归删除必须被拒绝。
- 影响分析、插件所有权、确认类型和恢复等级。
- 操作步骤排序、幂等性、备份命名和补偿计划。
- 审计记录脱敏与前后状态完整性。

## 故障注入与集成测试

- 在经过验证的临时目录中执行所有破坏性操作测试。
- 对备份、链接创建、原生注册、刷新、加载验证和审计写入逐步注入失败。
- 验证失败前不损坏来源；已移动的真实目录能够自动恢复或留下明确人工恢复材料。
- 重复启用、重复卸载、进程中断后重试和并发请求保持幂等。

## 平台测试

- Windows 覆盖 Junction 创建与解析、ReparsePoint、断链、盘符和占用错误。
- macOS/Linux 覆盖 Symbolic Link、相对和绝对目标、权限、断链与大小写差异。
- 三个平台都验证停用共享只删除链接，来源目录保持完整。

## 来源删除与插件生命周期

- 来源位置卸载自动升级为来源删除，并在确认前零修改。
- 任一依赖预检失败时来源不被删除。
- 删除成功后隔离备份不显示为已安装能力，永久清除需要第二次确认。
- 插件卸载保留共享 Skill，备份被修改的独占 Skill，并移除独占 MCP 配置。
- 插件更新冲突不会自动覆盖用户修改。

## API 与 UI 验收

- API 覆盖响应模型、业务错误、本地修改授权、并发冲突和幂等重试。
- 确认界面展示完整影响、用户修改、恢复等级和不可逆部分。
- 进行中、成功、失败、已回滚和需人工恢复状态清晰可见。
- 审计详情能够追溯每个步骤，但不泄露秘密。

## BDD
