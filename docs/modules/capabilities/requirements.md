# Capabilities 模块需求

本文是 Capabilities 模块需求事实来源。共享、卸载、来源删除、备份和回滚的执行要求见 [Operations 模块](../operations/requirements.md)。

## 目标

统一表达 Codex、OpenCode、Claude Code 及未来 Agent 中的 Skill、MCP Server 和 Agent 插件，让用户能够识别真实来源、各 Agent 安装、兼容性、健康状态和原生加载结果。

## 公共能力模型

- 区分逻辑能力、真实来源和 Agent 安装。
- 同名能力结合类型、Manifest 标识、来源和内容指纹识别，不自动错误合并。
- 每个安装独立记录 Agent、兼容性、来源、健康和原生加载状态。
- 对具有目录来源且目标 Agent 支持目录发现的能力提供同源共享；不满足条件时使用 Agent 原生配置模式或明确标记不支持。
- 文件已分发但 Agent 未原生加载时，不得显示为完整可用。

## Skill

- 解析 `SKILL.md`、描述、兼容性和内容指纹。
- 提供 Skill × Agent 状态矩阵，区分来源、共享安装、本地副本、缺失、冲突、断链和无效。
- SkillBridge 的扫描、聚合和状态识别逻辑逐步合并到 AgentHub，不继续形成独立应用。

## MCP Server

- 发现独立 MCP 和插件携带的 MCP，归一化身份、来源、传输方式、命令或端点、配置位置和启用状态。
- 展示 Tools、Resources、Prompts 和健康检查结果。
- 敏感变量只展示名称和是否已配置，不读取或保存明文值。
- 第一阶段完成只读发现和验证；第二阶段再开放安全配置变更。

## Agent 插件

- 仅管理 Agent 原生插件机制识别的插件。
- 发现已安装和可安装插件，展示版本、来源、Manifest、兼容性、更新和内含能力。
- 维护插件与内含 Skill、MCP 配置的所有权和共享引用关系。
- 插件更新与用户修改发生冲突时展示差异和影响，不自动覆盖。

## 验收边界

- 每种能力类型至少在两个 Agent 上完成真实发现，才能声明完整支持。
- 能够准确区分来源、安装、冲突、兼容性和原生加载状态。
- 不支持的发现或加载方式明确降级，不以目录或配置存在代替 Agent 原生验证。
- 完整支持还要求启用和停用行为确定且可重复，并通过对应 Adapter 契约测试。
- 变更失败不得损坏真实来源，必须由 Operations 提供经过验证的恢复路径。
- 涉及目录或原生配置的能力类型必须通过所支持平台的集成验证，未验证平台标记为实验性。
