# Sessions 模块需求

本文是 Sessions 模块需求事实来源。任务排队和自动推进归 [Workflows 模块](../workflows/requirements.md)。

## 概述

让同时运行多个 Agent 和多个内部会话的用户，集中发现真正需要介入的工作，并准确回到原生会话继续处理。

### 目标

1. **集中监控**：统一展示所有 Agent 的会话状态，避免在多个工具间切换
2. **精准介入**：自动识别需要用户介入的会话，减少无效检查
3. **精确恢复**：提供一键恢复功能，准确打开目标会话继续工作
4. **灵活管理**：支持用户标记、筛选、搜索会话，快速定位关注点
5. **状态透明**：明确标识状态来源和可信度，不误导用户决策

## 1. 会话发现与展示
**原型参考**: [session-management-prototype.html](../../prototypes/session-management-prototype.html) - [原型2.1], [原型2.2]

### 1.1 会话基本信息
每个会话至少展示：
- Agent 和 Profile 信息
- 原生会话 ID（稳定标识）
- 会话标题
- 项目或工作目录
- 运行状态
- 系统关注状态
- 用户跟进标记
- 当前目标/规划
- 最近活动
- 更新时间
- 状态来源和可信度

### 1.2 统计与汇总
- 首页按内部会话统计（进程、窗口和工具数量只作为诊断信息）
- Agent 提供目标、步骤、Todo 或结果时原样透传
- 缺失时不得推测进度或生成百分比

## 2. 状态管理
**原型参考**: [session-management-prototype.html](../../prototypes/session-management-prototype.html) - [原型2.2.3]

### 2.1 运行状态
会话运行状态包括：
- **执行中**：Agent 正在执行任务
- **等待授权**：等待用户授权某项操作
- **等待输入**：等待用户输入信息
- **等待验收**：任务完成，等待用户验收结果
- **执行中断**：任务异常中断或失败
- **已关闭**：会话已正常结束
- **状态未知**：无法确定当前状态

### 2.2 系统关注状态
- "是否需要系统介入"是独立关注维度，由统一状态和可信原生事件自动推导
- 不提供人工覆盖入口
- 等待授权、等待输入和执行中断在后续事件表明恢复执行后自动解除
- 等待验收只有在用户继续发送指令、会话明确关闭或 Agent 上报接受结果时解除
- 仅打开会话不能视为验收完成
- 推断状态必须展示来源和可信度，不得冒充 Agent 明确事件

## 3. 用户跟进标记
**原型参考**: [session-management-prototype.html](../../prototypes/session-management-prototype.html) - [原型2.3]

### 3.1 标记原则
- 用户跟进标记是对早期"不提供人工标记"边界的受控扩展
- 只允许记录后续处理意图，不允许人工改写系统关注状态
- 用户跟进标记是 AgentHub 本地元数据，不改变 Agent 原生运行状态
- 系统关注状态与用户跟进标记分别展示、筛选和统计
- 标记必须绑定稳定的 Agent/Profile 与原生会话 ID
- 会话重新发现后仍能恢复标记

### 4.2 待跟进标记
**原型参考**: [session-management-prototype.html](../../prototypes/session-management-prototype.html) - [原型2.3.1]

用户可以将暂停或需要稍后处理的会话标记为"待跟进"。

**字段规格**：

| 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `follow_up_mark` | boolean | 是 | false | 是否标记为待跟进 |
| `follow_up_tags` | string[] | 否 | [] | 跟进标签，如"待测试"、"需讨论" |
| `follow_up_note` | string | 否 | "" | 用户备注，最多500字符 |
| `follow_up_remind_at` | datetime | 否 | null | 提醒时间 |
| `marked_at` | datetime | 是 | 当前时间 | 标记时间 |

**预定义标签**：
- 待测试
- 需讨论
- 等待资源
- 低优先级
- 需优化
- 等待依赖

**自定义标签规则**：
- 标签长度：1-20 字符
- 每个会话最多 5 个标签
- 标签跨会话共享（输入时显示历史标签建议）

**提醒时间**：
- 快速选择：1小时后、3小时后、明天上午9:00、明天下午2:00、下周一上午9:00、自定义
- 不允许设置过去的时间
- 最多提前 30 天
- 到达提醒时间时，桌面通知（如果授权）

### 4.3 已忽略标记
**原型参考**: [session-management-prototype.html](../../prototypes/session-management-prototype.html) - [原型2.3.2]

用户可以将中断会话标记为"已忽略"，表示该中断是正常退出或无需处理。

**字段规格**：

| 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `ignored_mark` | boolean | 是 | false | 是否标记为已忽略 |
| `ignored_reason` | string | 否 | "" | 忽略原因，预定义选项或自定义 |
| `ignored_note` | string | 否 | "" | 补充说明，最多200字符 |
| `marked_at` | datetime | 是 | 当前时间 | 标记时间 |

**预定义忽略原因**：
- 正常退出
- 任务已取消
- 重复会话
- 测试会话
- 误报中断
- 其他（自定义）

**标记后效果**：
- 标记后不再显示在待处理列表中（默认隐藏）
- 不计入 Dashboard 统计数字
- 在列表中显示为半透明灰色背景（勾选"显示已忽略"时）

### 3.4 标记操作

#### 3.4.1 添加待跟进标记
1. 会话列表中点击"标记跟进"按钮，或右键菜单选择"标记为待跟进"
2. 显示标记对话框：标签选择（可多选）、备注文本框、提醒时间选择
3. 点击"保存"完成标记
4. 会话在列表中显示"待跟进"徽章

#### 3.4.2 添加已忽略标记
1. 会话列表中点击"忽略"按钮（仅对中断状态的会话显示）
2. 显示忽略对话框：忽略原因单选、补充说明文本框
3. 点击"确认忽略"完成标记
4. 会话在列表中显示为半透明（默认隐藏）

#### 3.4.3 取消标记
1. 已标记的会话显示"取消标记"按钮
2. 点击后显示确认对话框："确定取消标记吗？备注和提醒将被删除"
3. 确认后清除标记数据
4. 用户可以手动取消跟进标记，但不能用该操作清除等待授权、等待输入或执行中断等真实状态

#### 3.4.4 批量标记
- 支持多选会话（复选框）
- 批量操作菜单：批量标记为待跟进、批量忽略、批量取消标记

### 3.5 标记持久化

**存储结构**：

```sql
CREATE TABLE session_annotations (
    id INTEGER PRIMARY KEY,
    agent_profile_id TEXT NOT NULL,
    native_session_id TEXT NOT NULL,
    follow_up_mark BOOLEAN DEFAULT FALSE,
    follow_up_tags TEXT,  -- JSON array
    follow_up_note TEXT,
    follow_up_remind_at DATETIME,
    ignored_mark BOOLEAN DEFAULT FALSE,
    ignored_reason TEXT,
    ignored_note TEXT,
    marked_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    UNIQUE(agent_profile_id, native_session_id)
);
```

**同步机制**：
- 标记操作立即写入数据库
- 会话刷新时自动合并标记数据
- 标记绑定到 `agent_profile_id + native_session_id`
- Agent 重新发现会话时，标记仍然存在

**清理策略**：
- 会话最后活动超过 90 天且已关闭，自动清理标记
- 用户可在设置中手动清理所有已忽略的历史会话标记

## 4. 筛选与搜索
**原型参考**: [session-management-prototype.html](../../prototypes/session-management-prototype.html) - [原型2.2.1], [原型2.2.2]

### 4.1 会话筛选

#### 4.1.1 筛选维度

会话列表支持以下筛选维度，可组合使用：

| 筛选维度 | 选项 | 默认值 |
|---------|------|--------|
| 运行状态 | 全部/执行中/等待授权/等待输入/等待验收/执行中断/已关闭/状态未知 | 全部 |
| 关注状态 | 全部/需要介入/无需介入 | 全部 |
| 用户标记 | 全部/待跟进/已忽略/未标记 | 全部（隐藏已忽略） |
| Agent 类型 | 全部/Codex/OpenCode/Claude Code/Hermes | 全部 |
| Agent Profile | 全部/[具体 Profile 名称] | 全部 |
| 项目/目录 | 全部/[具体项目路径] | 全部 |
| 更新时间 | 全部/最近1小时/今天/最近7天/更早 | 全部 |

#### 4.1.2 筛选组合逻辑
- 不同维度之间使用 **AND** 逻辑（必须同时满足）
- 同一维度内多选使用 **OR** 逻辑（满足任一即可）

#### 4.1.3 快速筛选入口
主页面统计数字支持点击跳转到对应状态的会话列表：

| 统计项 | 点击后筛选条件 |
|--------|---------------|
| 会话总数 | 运行状态=全部，用户标记≠已忽略 |
| 执行中 | 运行状态=执行中 |
| 等待介入 | 关注状态=需要介入 |
| 等待验收 | 运行状态=等待验收 |
| 任务中断 | 运行状态=执行中断，用户标记≠已忽略 |

#### 4.1.4 筛选器 UI
- **位置**：会话列表顶部，可折叠的筛选栏
- **默认状态**：折叠，只显示激活的筛选条件标签
- **展开状态**：显示所有筛选维度的下拉框或多选框
- **清除筛选**：提供"清除全部筛选"按钮
- **筛选计数**：显示当前筛选结果数量，如"显示 15/50 个会话"

#### 4.1.5 特殊筛选规则

**已忽略会话处理**
- **默认行为**：隐藏已忽略的会话
- **显示选项**：提供"显示已忽略"复选框
- **视觉区分**：已忽略会话显示为半透明灰色背景
- **统计排除**：已忽略会话不计入 Dashboard 统计数字

**已关闭会话处理**
- **默认行为**：显示最近7天内关闭的会话
- **配置选项**：用户可设置显示时间范围（1天/7天/30天/全部）
- **自动清理**：超过保留期的已关闭会话从列表移除（但保留在数据库中）

#### 4.1.6 筛选持久化
- 用户设置的筛选条件保存在浏览器 localStorage
- 页面刷新后恢复上次的筛选条件
- 提供"重置为默认"选项

### 4.2 会话搜索

#### 4.2.1 搜索范围

| 字段 | 权重 | 匹配方式 |
|------|------|---------|
| 会话标题 | 高 | 模糊匹配 |
| 当前目标 | 高 | 模糊匹配 |
| 项目名称 | 中 | 模糊匹配 |
| Agent 名称 | 中 | 精确匹配 |
| 当前步骤 | 低 | 模糊匹配 |
| 会话 ID | 低 | 前缀匹配 |

#### 4.2.2 搜索行为
- **实时搜索**：输入后 300ms 自动执行搜索（防抖）
- **最小长度**：至少输入 2 个字符才触发搜索
- **大小写**：不区分大小写
- **高亮显示**：搜索结果中匹配的关键词高亮显示

#### 4.2.3 搜索 UI
- **位置**：筛选栏左侧，独立的搜索框
- **占位符**：显示"搜索会话标题、目标、项目..."
- **清除按钮**：输入内容后显示"×"清除按钮
- **无结果提示**：无匹配时显示"未找到匹配的会话，尝试调整搜索关键词或筛选条件"

#### 4.2.4 搜索与筛选的关系
- 搜索和筛选可以组合使用
- 先应用筛选条件，再在筛选结果中搜索
- 清除筛选不清除搜索词，反之亦然
- 提供"清除搜索和筛选"总按钮

## 5. 会话显示配置

### 5.1 列表布局

#### 5.1.1 卡片式布局（默认）
每个会话显示为一张卡片：

**卡片头部**：
- 左上：Agent 图标和类型
- 右上：状态徽章（执行中/等待输入等）
- 用户标记徽章（待跟进/已忽略）

**卡片主体**：
- 标题：会话标题（最多 2 行，超出显示省略号）
- 副标题：项目名称或工作目录
- 当前目标：显示 Agent 当前目标（最多 3 行）
- 最近活动：显示最后一条消息或事件摘要（最多 2 行）

**卡片底部**：
- 左下：更新时间（相对时间，如"5分钟前"）
- 右下：操作按钮（打开、标记、刷新、更多）

#### 5.1.2 紧凑列表布局（可选）
单行显示，适合大量会话：
- Agent 图标 | 状态徽章 | 标题 | 项目 | 更新时间 | 操作按钮

#### 5.1.3 表格布局（可选）
适合需要排序和对比：
- 列：Agent、状态、标题、项目、当前目标、更新时间、操作

### 5.2 可配置显示项

| 显示项 | 默认 | 说明 |
|--------|------|------|
| Agent 图标 | 显示 | Agent 产品类型图标 |
| Profile 名称 | 隐藏 | Agent 配置名称 |
| 当前目标 | 显示 | Agent 正在执行的目标 |
| 当前步骤 | 隐藏 | 当前具体步骤 |
| 最近活动 | 显示 | 最后一条消息或事件 |
| 更新时间 | 显示 | 最后活动时间 |
| 状态来源 | 隐藏 | 状态推导来源和可信度 |
| 精确恢复支持 | 隐藏 | 是否支持精确恢复 |

### 5.3 状态可视化

#### 5.3.1 运行状态颜色
- 执行中：蓝色（#3B82F6）
- 等待授权：橙色（#F59E0B）
- 等待输入：黄色（#EAB308）
- 等待验收：紫色（#A855F7）
- 执行中断：红色（#EF4444）
- 已关闭：灰色（#6B7280）
- 状态未知：浅灰（#9CA3AF）

#### 5.3.2 关注状态标识
- 需要介入：在卡片左侧显示红色竖线
- 无需介入：无特殊标识

#### 5.3.3 用户标记标识
- 待跟进：黄色星标图标 + "待跟进"文字
- 已忽略：灰色划掉图标（在显示已忽略时）
- 提醒：红色时钟图标（有提醒且未到期）
- 提醒到期：红色闪烁时钟图标（到达提醒时间）

#### 5.3.4 可信度指示
当显示"状态来源"时：
- 高可信：绿色实心圆
- 中等可信：黄色半圆
- 低可信：灰色空心圆

### 5.4 会话排序

#### 5.4.1 默认排序
- 主排序：更新时间（最新在前）
- 次排序：会话 ID

#### 5.4.2 可选排序方式
- 按更新时间（最新/最旧）
- 按创建时间（最新/最旧）
- 按标题（A-Z/Z-A）
- 按项目名称（A-Z/Z-A）
- 按 Agent 类型
- 按状态（按优先级：中断>等待授权>等待输入>执行中>等待验收>未知>已关闭）

#### 5.4.3 分组排序
可选择分组展示：
- 按 Agent 类型分组
- 按项目分组
- 按状态分组
- 按用户标记分组（待跟进/未标记/已忽略）

#### 5.4.4 虚拟滚动
- 会话数量超过 50 个时启用虚拟滚动
- 只渲染可见区域的卡片
- 滚动流畅，性能优化

### 5.5 空状态

#### 5.5.1 无会话
- 显示："还没有发现任何会话"
- 建议："确保已配置并启用 Agent Profile"
- 操作："前往配置 Agent"按钮

#### 5.5.2 筛选无结果
- 显示："未找到匹配的会话"
- 建议："尝试调整筛选条件或搜索关键词"
- 操作："清除筛选"按钮

#### 5.5.3 全部已忽略
- 显示："所有会话都已被忽略"
- 建议："勾选'显示已忽略'查看它们"
- 操作："显示已忽略"复选框

## 6. 刷新与同步策略

### 6.1 刷新时机

#### 6.1.1 自动刷新
- **间隔**：可配置，默认 60 秒
- **范围**：所有已启用的 Agent Profile
- **条件**：页面可见且没有正在进行的手动刷新
- **暂停**：用户正在操作时（如展开卡片、编辑标记）暂停自动刷新

#### 6.1.2 手动刷新
- **触发**：用户点击"刷新"按钮
- **范围**：全部或单个 Profile
- **反馈**：显示刷新进度和加载指示器

#### 6.1.3 事件驱动刷新（未来）
- 监听 Agent 事件流（如果支持）
- 实时更新会话状态，无需轮询
- 当前状态：仅 OpenCode Server 计划支持

### 6.2 刷新流程

1. **触发刷新**：自动定时、手动点击或监听到事件
2. **执行刷新**：并发调用所有已启用 Profile 的 Adapter，超时 30 秒
3. **合并数据**：以 `Profile ID + 原生会话 ID` 为键合并会话，保留本地 `SessionAnnotation`
4. **更新 UI**：刷新会话列表和统计数字，保持用户当前的筛选和滚动位置
5. **错误处理**：单个 Profile 刷新失败不影响其他 Profile，显示错误提示

### 6.3 性能优化

#### 7.3.1 并发控制
- 最多同时刷新 5 个 Profile
- 超出的 Profile 排队等待

#### 6.3.2 缓存策略
- Agent 会话列表缓存 60 秒
- 手动刷新强制清除缓存
- 单个会话详情缓存 30 秒

#### 6.3.3 智能刷新
- 优先刷新有活跃会话的 Profile
- 长时间无变化的 Profile 降低刷新频率
- 用户聚焦某个 Profile 时提高其刷新频率

#### 6.3.4 刷新 UI 反馈
- **全局刷新**：页面顶部显示进度条
- **单个 Profile**：对应卡片显示加载动画
- **刷新完成**：短暂显示"已更新"提示

**刷新状态**
- 正在刷新：显示动画和进度
- 刷新成功：显示更新时间
- 刷新失败：显示错误图标和原因

**刷新控制**
- 提供"刷新全部"按钮
- 提供"刷新此 Profile"按钮（在 Profile 筛选时）
- 显示"上次刷新时间"
- 提供"暂停自动刷新"选项

### 6.4 冲突处理

#### 6.4.1 本地标记与远程状态冲突
- **原则**：本地用户标记优先
- **场景**：会话在远程已关闭，但本地标记为待跟进
- **处理**：保留用户标记，更新运行状态，显示状态差异提示

#### 6.4.2 会话消失处理
- **场景**：上次刷新存在，本次刷新不存在
- **可能原因**：会话被删除、Profile 配置变化、Adapter 故障
- **处理**：
  - 保留会话记录，标记为"已消失"
  - 显示警告："此会话在 Agent 中未找到，可能已被删除"
  - 允许用户手动删除记录或等待自动清理

#### 6.4.3 会话 ID 冲突
- **场景**：同一 Profile 下出现重复的原生会话 ID
- **处理**：记录错误日志，只保留最新的会话数据

## 8. 验收标准

### 8.1 精确恢复与产品边界

#### 9.1.1 精确恢复要求
- 打开会话必须按稳定原生会话 ID 恢复指定会话
- 不能只打开 Agent 首页或激活窗口
- 恢复入口按优先级：官方 API、CLI Resume、原生插件或深度链接、原终端/桌面窗口

#### 9.1.2 产品边界
- Sessions 模块不提供消息输入、权限批准或任务调度
- 自动发送工作由 Workflows 模块通过独立执行 Adapter 完成
- 只能探测进程或窗口时属于有限接入，不纳入核心会话统计

### 8.2 接入等级

- **完整接入**：多会话发现、稳定身份、独立状态和精确恢复均通过真实验证
- **部分接入**：缺少规划、事件或部分状态，但仍能识别并精确恢复会话
- **有限接入**：只能判断 Agent 是否运行，不能可靠识别和恢复内部会话

### 8.3 验收边界

#### 8.3.1 会话发现与身份验收

| 验收项 | 验收标准 | 测试场景 |
|--------|----------|----------|
| 多会话隔离 | 同一 Agent 多个会话身份和状态互不串扰 | Codex 打开 3 个会话，验证标题、状态、目标各自独立 |
| 稳定会话 ID | 会话 ID 由 Profile ID + 原生会话 ID 组成 | 刷新后验证会话 ID 不变，标记数据仍能关联 |
| 多 Agent 支持 | 至少两个 Agent 完成多会话发现验证 | 同时运行 Codex 和 OpenCode，两者会话都能正确发现 |
| 有限接入标识 | 有限接入不显示为完整会话，不计入统计 | 只能探测进程的 Agent 不在会话列表显示 |

#### 9.3.2 状态管理验收
