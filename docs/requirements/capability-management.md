# Skill、MCP 与插件管理需求

## 目标

将 AgentHub 从会话聚合管理台扩展为本地能力管理中枢，统一管理 Codex、OpenCode、Claude Code 及未来 Agent 中的 Skill、MCP Server 和插件。

## 共有能力

所有能力类型都需要支持：发现、所有者或来源识别、各 Agent 可用性、兼容性、健康状态、启用与停用、审计历史及安全恢复。不同工具的原生格式由对应适配器负责处理。

## Skill 管理

- 复用 `src/skill_bridge/` 中的扫描器、目录聚合、状态模型、备份、Junction 和回滚设计。
- 提供 Skill × Agent 状态矩阵，区分源目录、共享链接、本地副本、缺失、冲突、断链和无效状态。
- 未经明确确认和备份，不得覆盖真实目录。

## MCP 管理

- 从各个受支持 Agent 的配置中发现 MCP Server 定义。
- 统一表示 Server 身份、传输方式、命令或端点、启用状态、所属配置、暴露工具和健康检查结果。
- UI、日志、导出和诊断信息必须隐藏密钥等敏感内容。
- 应用配置前先验证，并保留旧版本用于回滚。

## 插件管理

- 通过原生 Manifest 或 Catalog 发现已安装及可安装插件。
- 展示版本、来源、内含 Skill/MCP/App、兼容性、启用状态、可用更新和校验失败信息。
- 安装、更新、启用、停用和移除必须经过原生插件适配器，并产生审计记录。
- 移除时必须区分生成缓存和用户编写的插件数据。

## 范围边界

首个版本仅支持本地单用户，不包含云端市场、团队策略下发、自动更新或静默执行破坏性清理。

## 验收方向

每种能力类型至少需要在两个 Agent 上完成独立发现以及可确定的启用、停用行为，之后才能标记为“完整支持”。
